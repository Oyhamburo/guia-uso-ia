Primero: la IA no piensa por vos.

La diferencia entre un uso pobre y uno fuerte no está en “el prompt mágico”, sino en el marco de decisión que ponés antes de pedirle algo.

Bueno

Usarla como socio de trabajo

Sirve para explorar alternativas, ordenar información, generar borradores, detectar huecos y acelerar ciclos de prueba.

Cuidado

Confundir seguridad con certeza

Una respuesta puede sonar impecable y estar mal. La confianza del tono no es evidencia.

Evitar

Delegar juicio crítico

Si no podés explicar por qué una respuesta es correcta, todavía no tenés una respuesta: tenés una hipótesis.

Un buen pedido reduce ambigüedad.

La IA necesita rol, objetivo, contexto, restricciones, formato esperado y criterio de aceptación.

Plantilla base

Actuá como [rol]. Necesito [objetivo concreto]. Contexto: [datos, audiencia, situación]. Restricciones: [no hacer / límites / tono / longitud]. Criterio de calidad: [cómo sabremos que está bien]. Formato de salida: [lista, tabla, pasos, código, etc.]. Antes de responder, preguntame lo que falte.

Qué cambia realmente

  • Menos relleno: la respuesta va al punto.
  • Menos invento: obliga a declarar supuestos.
  • Mejor iteración: podés corregir una dimensión por vez.
  • Más control: la IA trabaja sobre tu estándar, no sobre uno genérico.

Verificar es parte del trabajo, no un extra.

En temas importantes, la salida de IA debería pasar por una etapa de contraste: fuentes, pruebas, lectura humana o ejecución técnica.

Fuentes¿De dónde sale esta afirmación?
Pruebas¿Qué evidencia concreta la sostiene?
Contraejemplos¿Cuándo sería falso?
Riesgo¿Qué pasa si está mal?
Iteración¿Qué aprendimos para la próxima versión?
Regla práctica: cuanto más irreversible sea una decisión, más evidencia externa necesitás. Para ideas exploratorias alcanza un borrador; para salud, legal, seguridad, dinero o producción, no.
Pregunta abierta

Pero si la IA produce cientos o miles de líneas, ¿cómo hago para verificar tanto código?

El ecosistema tiene capas.

“Estoy usando Claude” o “estoy usando GPT” no alcanza para describir qué ocurre. Un modelo puede llegar a vos a través de distintas empresas, productos y formas de pago.

1. Modelo

El motor que interpreta y genera: GPT, Claude, Gemini, Llama, Qwen, DeepSeek y otros.

capacidad
2. Proveedor

La empresa o infraestructura que ejecuta el modelo y define precio, disponibilidad, privacidad y límites.

acceso
3. Producto

La interfaz que usás: un chat, un editor de código, una terminal, una app propia o una plataforma web.

experiencia
4. Agente

La capa que además puede leer archivos, ejecutar comandos, llamar herramientas y trabajar en varios pasos.

acciones
No toda inteligencia artificial es un LLM. “Modelo” es una categoría amplia. Algunos trabajan con lenguaje; otros están entrenados para crear, interpretar o transformar imágenes, audio y video.
AaLenguaje y razonamiento

Sí, son LLMs: modelos grandes de lenguaje. Trabajan principalmente con texto y código, aunque algunos también entienden imágenes, audio o video.

GPT · Claude · Gemini · Qwen — LLMs, varios de ellos multimodales
▧Imagen

No son LLMs: son modelos generativos de imagen. Crean o modifican píxeles a partir de texto, referencias, máscaras u otras imágenes.

GPT Image · Midjourney · FLUX · Imagen — generación y edición de imagen
♫Audio y voz

No son un único tipo de modelo: Whisper reconoce voz; ElevenLabs sintetiza voz; Suno genera música. Pueden usar transformers, pero eso no los convierte automáticamente en LLMs.

Whisper — transcripción · ElevenLabs — voz · Suno — música
▶Video

No son LLMs: son modelos generativos de video. Producen o editan secuencias visuales manteniendo movimiento, tiempo y consistencia entre cuadros.

Sora · Veo · Runway — generación y edición de video
Generador, editor y producto tampoco son lo mismo: el generador crea contenido; el editor transforma material existente; el producto —por ejemplo una app de diseño o video— puede usar varios modelos por detrás.

Thinking / reasoning effort

Algunos modelos permiten indicar cuánto esfuerzo de razonamiento deben usar antes de responder. Más effort puede ayudar en código, matemática o planificación, pero normalmente aumenta el tiempo y el consumo. Según el producto puede aparecer como thinking, extended thinking, reasoning effort o funcionar automáticamente.

Más thinking no garantiza una mejor respuesta: depende de la tarea y del modelo.

¿Qué estás pagando y qué te llevás?

Una suscripción, una API key y un agregador resuelven problemas diferentes. Pueden convivir, pero normalmente se facturan por separado.

OpciónQué comprásCómo se cobraCuándo tiene sentido
Suscripción a un chatUna aplicación terminada: interfaz, historial, archivos y funciones del producto.Abono mensual con límites definidos por la app.Conversar, investigar, redactar o analizar sin configurar infraestructura.
API keyPermiso para que software propio consuma un modelo directamente.Generalmente por uso: tokens, imágenes, audio o llamadas.Automatizaciones, productos, scripts y control técnico del flujo.
OpenRouterUna API unificada y saldo para acceder a modelos de múltiples proveedores.Consumo según el modelo elegido y las condiciones del servicio.Comparar modelos o cambiar de proveedor sin integrar cada API por separado.
CursorUn editor de código con contexto del proyecto y funciones de IA integradas.Plan del producto; sus límites y modelos dependen del plan vigente.Programar con asistencia dentro de una experiencia visual de IDE.
OpenCodeUn agente de programación que opera desde la terminal y se conecta a modelos.La herramienta y el consumo del modelo son capas diferentes.Trabajar con archivos, comandos y tareas de código desde un flujo más configurable.
Ejemplo

Pagar ChatGPT no equivale a tener crédito de API

La suscripción paga el producto ChatGPT. Una aplicación propia que llama a la API usa otra vía de acceso y, normalmente, otra facturación. El modelo puede pertenecer a la misma empresa, pero el contrato de uso no es el mismo.

Ejemplo

El mismo modelo puede sentirse distinto

En un chat recibe tu conversación. En Cursor puede recibir archivos del proyecto. En un agente de terminal puede además ejecutar comandos. El motor puede ser igual; cambian el contexto disponible, las herramientas y el control del flujo.
